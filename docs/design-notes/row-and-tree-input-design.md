## 1. 目的と決定の境界

CSV ファイル、Markdown 表からフォルダ／ファイル階層を組み立て、罫線を使う tree 入力も扱えるようにする。各入力を共通の階層モデルへ接続し、preview / validate / create と既存の安全機構を共通適用することを前提とする。

2026-10-20 にユーザーが決定した基本方針は次の 3 点。

1. 行データは CSV ファイルと Markdown 表の両方を受け付ける。
2. 親子関係は id / parent_id 方式と親パス方式の両方を、列名で判別して受け付ける。
3. 既存の 2 スペース tree ブロックの互換性を維持し、`├──` / `└──` / `│` 形式も追加する。

2026-10-21 に具体化した D01〜D22 の推奨案をすべて採用した。[決定記録](../decisions.md)にユーザー回答を記録している。以下の列名、型値、選択方法、CLI 名称、診断仕様、入力例・期待結果は採用済み仕様である。位置情報の内部保持方法など、明記した実装上の裁量は仕様上の未決事項とは区別する。

## 3. 行データの列と階層

### 3.1 列・値の採用仕様

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D01 | 列名: A 厳密な英小文字の標準名のみ / B 大文字小文字や別名も許す（例 node_id、parent、kind） | A。自動判別の誤認を減らす。ヘッダーの外側空白は除去、重複ヘッダーはエラー。別名や日本語列名は設けない。 |
| D02 | 型: A 必須 type 列で file / directory / B dir 等の別名も許す / C 末尾 `/` や拡張子で推定 | A。拡張子のないファイルと空ディレクトリを一意に表せる。大文字・空値・未知値をエラーとし、name の末尾 `/` との併用は拒否する。 |
| D03 | 根・ID・空値: A parent の空値だけを根とする / B NULL、0、`.` 等も根とする。ID は文字列 / 数値変換 | A＋文字列。`001` と `1` は別 ID。id / name / type は空不可、parent_id / parent_path の空セルのみ根。文字列 `NULL` は特別扱いしない。 |
| D04 | 行順: A 親の先行を要求 / B 順不同を許す。兄弟順は入力順 / 名前順 | B＋入力順。全行を読んで参照解決し、親の後置を許す。兄弟・根はそれぞれの元の行順で安定させる。 |
| D05 | 親パスが指す親の省略: A 拒否 / B 暗黙の directory を作る | A。意図しない生成と型の推定を避け、全祖先を明示する。 |
| D06 | 両方式の列がある: A 曖昧として拒否 / B id 方式優先 / C 両方を照合 | A。列名で方式を決め、データ値による黙示の切替を避ける。無関係な追加列は無視するが、予約列の部分的な混在はエラーにする。 |
| D07 | 名前・パス: A 単一セグメントの name と `/` 区切り相対 parent_path / B name にもパスを許す。空白は保存 / trim | A＋値の空白保存。空白だけの name は拒否、空白だけの parent は根とみなさずエラー。ID も trim せず厳密一致させる。ヘッダーの処理とは区別する。 |

採用した必須列は次のとおり。階層判別に用いる列名は標準英小文字の下記のみとし、type 値は `file` / `directory` のみとする。列名・型値に別名を設けない。D06 のとおり、無関係な追加列は無視する。

| 方式 | 必須列 | 各行の意味 |
| --- | --- | --- |
| ID 方式 | `id,parent_id,name,type` | id は入力対象全体で一意な非空文字列。parent_id が空なら根、その他は同対象の id 参照。 |
| 親パス方式 | `parent_path,name,type` | parent_path は生成先から見た親の相対パス。空なら根。自身の出力相対パスは parent_path と name を結合して求める。 |

列名による方式判別: `id` / `parent_id` のどちらかがあれば ID 方式の完全な列組を要求。`parent_path` があれば親パス方式を要求。両方の系統があれば D06 の曖昧エラーとする。`name,type` だけでは方式を推定しない。無関係な Markdown 表を自動候補にする条件は §6 で別途扱う。

parent_path の表記は `project/src`。先頭・末尾 `/`、空セグメント、`.`、`..`、バックスラッシュ、絶対パス、ドライブ指定を拒否し、危険な値を正規化で救済しない。name は `/` と `\` を含まない 1 セグメントとし、禁止文字・制御文字も拒否する。生成先の外への解決結果は常に拒否する。これらは行データの規定であり、既存 tree の有効入力の互換性は維持する。既存 tree への影響は実装時の互換性試験で確認する。

### 3.2 CSV と Markdown 表の解釈

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D08 | CSV: A カンマ固定・二重引用符対応 / B 区切り自動推定。改行セルを許可 / 拒否。文字コード UTF-8 のみ / 複数対応 | A、UTF-8（先頭 BOM 許可）、LF / CRLF 対応。引用セル内のカンマ・改行と `""` による引用符を解釈し、不正な引用・列数不一致・不正 UTF-8 はエラー。CSV 構文上の改行セルは受理し、name 等で禁止する制御文字は意味検証で拒否する。文字コード推定を避ける。 |
| D09 | Markdown 表: A 限定した表構文を定義 / B 任意の Markdown 拡張を許す。セルは平文 / 表示文字列へ変換 | A＋平文。ヘッダーと区切り行を必須とし、任意の外枠パイプ、区切り行の配置指定 `:` を許す。セル両端の配置用空白を除去し、`\|` と `\\` だけをアンエスケープ。コードスパン内のパイプを区切りにしない。強調・リンク・HTML・実体参照・コードスパンの装飾は値へ自動変換せず、対象セルにあればエラーとする。複数物理行のセルや結合セルは非対応。 |

CSV は先頭行をヘッダーとし、完全な空行は読み飛ばす。カンマだけの行は空レコードとして必須値エラーにする。余分な空白を CSV の値から勝手に除去しない。ヘッダーより後の BOM は通常の値であり、BOM 除去を繰り返さない。

Markdown 表の空セルは空文字とし、欠けたセルを空文字で補わず列数不一致にする。CSV の引用規則を Markdown 表へ流用しない。表の外の本文や通常のコードフェンス内の表らしい記述は候補から除外する。CSV と Markdown ではセル外側空白の意味が違うため、前後空白が必要な名前の完全な相互変換は本仕様の対象外として明示する。

### 3.3 同じ階層を表す架空例

以下は D01–D09 の採用仕様に基づく。すべて出力先の下に `project/` を作り、その下に `src/index.ts` と `README.md` を置く。ID 方式の行順は親先行だが、D04 では子が先でも参照解決できる。

ID 方式の CSV:

```csv
id,parent_id,name,type
p,,project,directory
s,p,src,directory
i,s,index.ts,file
r,p,README.md,file
```

親パス方式の CSV:

```csv
parent_path,name,type
,project,directory
project,src,directory
project/src,index.ts,file
project,README.md,file
```

ID 方式の Markdown 表:

| id | parent_id | name | type |
| --- | --- | --- | --- |
| p | | project | directory |
| s | p | src | directory |
| i | s | index.ts | file |
| r | p | README.md | file |

親パス方式の Markdown 表:

| parent_path | name | type |
| --- | --- | --- |
| | project | directory |
| project | src | directory |
| project/src | index.ts | file |
| project | README.md | file |

空ディレクトリは directory 行だけで表現し、子の有無による型推定は行わない。

## 4. 既存 tree と罫線 tree

既存入力例（現行でも利用できる形）:

```tree
project/
  src/
    index.ts
  README.md
```

罫線入力例（採用済み・未実装。上の例と同じ階層）:

```tree
project/
├── src/
│   └── index.ts
└── README.md
```

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D10 | 罫線の深さ: A `│   ` / `    ` を 1 単位とし `├── ` / `└── ` を接続子とする / B 可変幅や ASCII の `+--` も許す | A。子の深さは前置単位数＋1、無接続の根は深さ 0。タブや不完全な単位、飛び級はエラー。描画と階層を一意に対応させる。 |
| D11 | 根: A 明示した実ノードのみ / B `.` を出力先そのものとして許す。複数根を許す / 単一根に限る | A＋複数根。根の名前も出力に含め、複数根は無接続行から始まる独立した tree とする。先頭から接続子だけの入力や `.` は拒否する。 |
| D12 | 型: A 既存同様末尾 `/` のみ / B 子があれば directory / C 拡張子でも推定 | A。空ディレクトリ・拡張子なしファイルを曖昧にしない。`src` の下に子があれば file 配下の子としてエラー。 |
| D13 | 混在・接続: A 対象ごとに形式を統一し接続の整合も検査 / B 2 スペースとの混在や接続の乱れを許す | A。最後の兄弟は `└──`、後続兄弟があれば `├──`、祖先の後続兄弟がある位置だけ `│` を許す。壊れた接続子を名前として救済しない。 |

末尾のファイル数集計など（例 `2 directories, 2 files`）は受け付けず、入力のノードに取り込まない。色のエスケープ列も拒否する。名前中の罫線文字まで一律禁止するかは避け、先頭構文として使われた位置だけを形式判定に使う。通常名との曖昧さが残る場合は明示指定で解消する。

既存 2 スペース形式の有効入力は残す。新形式の接続子規則を既存形式へ適用しない。これまで偶然受理されたタブ・罫線に似た名前・不正な構造の扱いは、互換性試験で区別する必要がある。

## 5. 共通の解析・検証・生成境界

次は採用仕様に基づく処理境界であり、関数や型の追加は今回行っていない。

```text
入力読取（元テキスト・位置を保持）
  → コンテナ判別・対象列挙・対象選択
  → CSV / Markdown 表 / 2スペース tree / 罫線 tree の解析
  → 列・参照・循環検査、共通階層モデルへの変換
  → 全体の構造・出力パス衝突・名前の安全性検証
  → preview: パス表示 / validate: 成否と診断 / create: 生成処理
```

共通階層モデルは現行 TreeNode の name / type / depth / children を基本にし、元入力への対応情報を付加する。ID は参照解決用として保持し、出力名にはしない。未解決参照や循環は TreeNode 化する前に検査し、無限再帰を避ける。位置情報を別マップで持つか型に付加するかは実装時の設計事項で、今回確定しない。

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D18 | preview: A 共通検証を通過した結果だけ表示 / B 現行同様に表示し警告を添える | A。3 コマンドが同じ入力を同じ階層として扱う。ただし現行 preview が表示できた不正入力はエラーになるため、正常入力の互換維持と区別する。この変更はユーザー採用済みであり、現行との差である。 |
| D19 | 重複・衝突: A 型を問わず同じ出力相対パスを拒否 / B 現行の型＋名前の重複判定を維持。大文字小文字差を常に拒否 / 実行先に合わせる | A＋移植性のため大文字小文字だけ異なるパスも衝突として拒否する。ID 重複は別検査。Unicode は勝手に正規化せず、見かけ上の同一性全般を保証するものではない。Unicode による衝突検出の実装上の限界は検証時に確認する。 |
| D20 | force と skip-existing の同時指定: A エラー / B 現行の force 優先を明文化 | A。既存説明に合わせ誤った上書きを避ける。どの入力でも同じ扱いにするが、今回コードは修正しない。 |

現行との差: D18 の共通検証は現行 preview にはない。D19 は現行の `type:name` による兄弟重複判定を強化し、同名異型や大小文字だけ異なる出力先も拒否する。D20 は現行の force 優先から同時指定エラーへ変更する。これらはすべて採用済みの実装要件であり、今回の文書更新では実装していない。

すべての入力で解析・意味検証は共通化し、create の dry-run / force / skip-existing / テンプレート適用 / 生成先パス安全性検証は同一の生成処理へ渡す。force は入力内の重複、循環、不正型、危険なパスを許可するオプションにしない。skip-existing も同様。

preview / validate は書込をせず、出力先がなくても実行できる静的な検証を担当する。生成先との包含関係や既存ファイルの衝突検査は create（dry-run を含む）で実行する。dry-run と実生成で入力検証の強度を変えず、dry-run は書込だけを抑止する。実行先の状態は変化するので、dry-run の成功は後続の実生成成功を保証しない。

同一出力パス衝突は書込前に全体検査する。実ファイルとの衝突・I/O エラーでは現行同様に途中まで生成される可能性があり、ロールバックや原子的生成は今回の追加要件にしない。シンボリックリンク等の実環境の制約を安全保証から隠さない。

## 6. 入力判別・Markdown 内の複数対象・CLI

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D14 | コンテナ判別: A 拡張子＋明示指定 / B 内容だけで推定 / C 常に指定必須 | A。`--input-format` 明示値が優先、auto では `.csv` は CSV、`.md` / `.markdown` は Markdown（拡張子の大文字小文字は無視）。未知拡張子は明示指定を求める。構文エラー後に別形式へ自動フォールバックしない。 |
| D15 | Markdown 複数対象: A 最初の tree を優先し、表だけなら一意時に自動選択 / B 全候補から一意なら選択、複数ならエラー / C 自動統合 | A。既存の複数 tree 文書の動作を保ち、表との意図しない統合を避ける。tree がなく表が 1 つなら表を自動選択、表が複数なら選択を要求する。対象間の統合は非対応。 |
| D16 | CLI: A 入力形式・対象・tree 構文を別指定 / B 1 オプションにすべて詰める | A。オプションは `--input-format auto\|csv\|markdown`、`--source tree:N\|table:N`、`--tree-style auto\|indent\|branches`。名称・値は採用済みで、既存 CLI には未追加。 |
| D17 | tree の内容判別: A 構文位置の接続子で判別し曖昧ならエラー / B 両 parser を順に試す | A。対象ブロック内に罫線の接続子があれば branches、なければ indent。根だけの同義な入力は indent として扱い、混在は D13 によりエラー。明示 style は自動判別より優先し、不一致ならエラー。 |

採用した対象列挙・選択手順:

1. Markdown の tree フェンスと階層入力候補の表を、元文書での開始順に列挙する。tree と table の番号は種類ごとに 1 始まり。通常のコードフェンス・引用例・リスト内の扱いは、トップレベルの tree フェンスと表のみを対象とする。tree フェンスは言語名が厳密に `tree` のものを対象とする。
2. 表の自動候補は `name` / `type` の少なくとも一方に加え、`id` / `parent_id` / `parent_path` のいずれかを含む表。完全な必須列かの検査はその後に行い、name または type の欠損を単なる「対象なし」にしない。候補条件さえ満たさない表は対象外なので、任意の欠損をすべて必須列エラーとして診断できるわけではない。関係ない表は無視する。明示された table:N もこの候補表の番号とする。
3. 明示 source があればそれのみ選択。番号不在や CSV への source 指定はエラー。source 未指定では最初の tree が優先、なければ候補表が 1 つなら選択。選択されない表やブロックは解析・検証・生成しない。
4. 候補なしは対象なしエラー。表だけが複数なら、候補の番号・元行を表示して source 指定を要求する。選択した対象が壊れていても次の候補へ切り替えない。

互換性への影響: 採用した D15-A は既存の「最初の tree」を維持する。D15-B/C は同じ Markdown の結果を変えるため採用しなかった。一方、正規表現による現行の抽出と、構文を意識した候補列挙では、本文の引用例や入れ子フェンス等で差が出る。対象は上記のトップレベル構文に限定する。標準的な現行入力を互換試験に含め、引用・リスト・入れ子フェンス等が誤って対象にならないことを確認する。新しい判別は、罫線に似た名前を持つ旧入力にも影響しうるため、`--tree-style indent` で明示指定できる。

以下は **採用済み・未実装の CLI 仕様例**。現行バージョンでは新オプションは利用できない。

```bash
# CSV の列名から親子関係方式を判別
treegen preview --input structure.csv --input-format csv
treegen validate --input structure.csv --input-format csv
treegen create --input structure.csv --input-format csv --output generated --dry-run

# Markdown の候補表を明示
treegen preview --input structure.md --input-format markdown --source table:1
treegen validate --input structure.md --source table:1
treegen create --input structure.md --source table:1 --output generated --skip-existing

# 2 番目の tree ブロックを罫線として解釈
treegen validate --input structure.md --source tree:2 --tree-style branches
treegen create --input structure.md --source tree:2 --tree-style branches --output generated --dry-run
```

CSV / 表への tree-style 指定は無関係な指定としてエラーにする。CSV の方式選択 CLI は設けず、決定済みの列名判別を用いる。罫線テキストの単独ファイルや Markdown 内の CSV フェンスは今回の入力形式に追加せず、tree は従来同様 Markdown の tree ブロック内で扱う。

## 7. エラー仕様・位置情報

| ID | 論点と選択肢（検討履歴） | 採用内容と理由 |
| --- | --- | --- |
| D21 | エラー停止: A 最初の 1 件 / B 可能な範囲で集約 | B。字句・構文が壊れて位置対応できない対象はそこで停止し、解析できた行の独立した意味エラーは集約。ID 解決不能から派生する子の型エラー等は重複表示を避ける。エラーがあれば生成を開始しない。 |
| D22 | 診断位置: A レコード番号だけ / B 元ファイルの物理行・列とレコード番号 | B。元テキストを保持し、CSV 改行セルの行範囲、Markdown の本文内の位置、関連する親・重複行も追えるようにする。 |

診断項目は code、入力ファイルの表示名、対象（table:1 等）、物理行・文字列の列（1 始まり）、列名、問題値、説明、関連行。以下に診断コードと表示例を示す。機械可読出力の新規 CLI は本仕様に含めない。列位置はバイト数やターミナル表示幅ではなく、元行の Unicode コードポイント数で数える。

CSV はヘッダーを含めた物理行番号と、ヘッダーを除くデータレコード番号を区別する。複数行セルは開始行・列と終了行・列を持ち、意味エラーでも元の引用セルを特定できるようにする。Markdown 表はヘッダー・区切り行を含む文書全体の行番号を用い、コードブロックはフェンスを含む元 Markdown の行へ対応させる。デコード・アンエスケープ後の値と元範囲の対応を残す。

診断例（すべて架空、コード・形式は未実装）:

```text
structure.csv:3:3 [PARENT_NOT_FOUND] parent_id="missing"
  data record 2: 参照先 id がありません
structure.csv:4:1 [DUPLICATE_ID] id="s"
  related structure.csv:3:1: 先に定義された id="s"
structure.md:12:7 [FILE_HAS_CHILD] parent_id="f"
  related structure.md:10:18: name="README.md", type="file"
structure.md:18:3 [UNSAFE_PATH] parent_path="../outside"
  出力先の外へ出るセグメントは使用できません
structure.csv:5:4-6:8 [INVALID_NAME] name="bad\nname"
  data record 4: 改行を含む名前は使用できません
```

最後の例は引用セルが物理 5–6 行にまたがる場合の位置範囲であり、構文上の CSV 改行受理と名前の安全性拒否を分離する例。表示時は制御文字・改行をエスケープし、任意値をターミナル制御として出力しない。

| エラー条件 | 問題値と関連位置 |
| --- | --- |
| 必須列欠損、同名ヘッダー、列数不一致 | ヘッダー行、欠けた列名（値は「なし」）、重複ヘッダーの両位置、または対象レコードの行範囲。 |
| 空 id / name、不正 type | 当該セルの空文字または原値と位置。type の許可値を提示。 |
| 親 ID 不在、親パス不在 | parent_id / parent_path の原値と位置。存在しない親を暗黙に作らない。 |
| 自己参照・循環 | 各 id / parent_id セルの行と値。例 `a → b → a` を示す。自己参照は同じ行の両列を示す。 |
| 重複 ID | 後の id セルと先の id セル。別名でも ID 重複なら拒否。 |
| 同一出力先衝突（同型・異型とも） | 計算した相対パス、両方の name / parent 列と行。force で解消しない。 |
| ファイル配下の子 | 子の親参照・行と、親の type / name・行。tree でも元入力の両行。 |
| 危険なパス・不正名 | 元の parent_path / name の値と行・列、禁止理由。正規化前に検査し、生成時も包含関係を検査。 |
| tree 深さ・接続不整合 | 元行の接続子や空白の範囲、問題文字をエスケープした値、必要なら祖先・直前兄弟の行。 |
| 対象なし・選択が曖昧・番号不在 | 指定値、候補の開始行と番号。元行が存在しない場合は行番号を捏造しない。 |
| CSV 引用不整合、Markdown セル構文不正 | 引用開始やセルの行・列と問題値、解析を停止した範囲。 |
| 既存ファイル衝突・書込失敗 | 生成対象の相対パスと入力元行。入力不正と実行先の状態の問題を区別。 |

## 8. 検証ケースと机上追跡

以下は採用仕様に基づく実装時の検証項目であり、今回テストを追加・実行して新機能を検証したものではない。

| ケース | 採用仕様の期待結果 |
| --- | --- |
| §3 の CSV 2 種・表 2 種・§4 の tree 2 種 | 同じ 4 ノード（directory 2、file 2）。根 project の子は src、README.md の順。index.ts は src の子。 |
| ID の子 i を s より前に移動 | 参照を全件読取後に解決して同じ親子関係。兄弟の相対順は元行順。 |
| id が `001` と `1`、空 parent_id の根が複数 | 別 ID として受理。各根が出力先の直下に置かれる。 |
| 空 directory / 拡張子のない file | type または tree の末尾 `/` に従って区別。 |
| 親 ID missing、親パス project/absent | 不在の原値・元行を診断。暗黙の親は作らない。 |
| 親パス project/src に対し project または src の行を省略 | 全祖先の明示が必要なためエラー。途中の directory を暗黙に作らない。 |
| a が a を参照 / a が b、b が a を参照 | 自己参照 / 循環を木への変換前に検出。関係行と経路を提示。 |
| 同一 id、別 id で同じ出力パス、同名 file と directory | ID 重複と出力衝突を区別して拒否。後勝ちにしない。 |
| README.md と readme.md を同じ親に置く | 実行環境や型によらず、大文字小文字だけ異なる出力先の衝突として拒否。 |
| file 行の id またはパスを親として子を置く | FILE_HAS_CHILD。親・子両行を示す。 |
| type が dir / 空、name 列欠損 | INVALID_TYPE / 必須値 / 必須列の診断を区別。 |
| name が `../x`、parent_path が `/tmp`、`C:\\x`、`a/../b` | 危険なパスとして拒否。値を清掃して受理しない。 |
| CSV の BOM、CRLF、引用セル内カンマ、`""` | 構文として解析。値の安全性は別検査（例: 引用符を含む name は禁止記号エラー）。 |
| CSV の改行セル、閉じない引用符、列数違い | 改行セルは行範囲を保持して意味検査、引用不整合は構文停止、列数違いはレコード位置付き診断。 |
| 表の `\|`、コードスパン内 `\|`、空セル、欠けたセル | 区切りとして誤分割しない。復元した `\|` や装飾は規則によりエラー。空値と列数違いを区別。 |
| 既存 2 スペースの飛び級 / 罫線の `└──` の後に同階層兄弟 | 元の行を示す深さエラー / 接続整合エラー。 |
| 罫線例の `src/` を `src` にする | src が file となり index.ts を子に持つため拒否。 |

| 候補表 2 個だけ / 候補なし / 未知拡張子 | 曖昧・対象なし・明示形式要求をそれぞれ診断。 |
| 同じ入力で preview / validate / create --dry-run | 静的意味検証の結果は一致。create だけが生成先状態も確認。dry-run は書込なし。 |
| 既存ファイルに既定 / skip / force | エラー / スキップ / 上書き。全入力で同じ意味。force＋skip の同時指定は D20 によりエラー。 |

机上追跡の記録: 正常例では p → s → i と p → r が `project/src/index.ts` と `project/README.md` に一致し、親パス例および両 tree 例でも同じ構造となる。罫線例の `│` は src に後続兄弟 README.md があるため必要。異常例では missing は ID 索引に存在せず、循環は根探索だけでは見逃すため全 ID の巡回検査が必要となる。同名異型は現行の重複検査で検出されないので D19 が必要。2026-10-20 に行ったこの机上追跡は、2026-10-21 のユーザー採用内容とも整合する。実装の動作検証を代替するものではない。
