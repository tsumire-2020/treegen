# ユーザー決定記録

## 2026-10-20: 行データ入力・罫線 tree 入力

### 当日の決定

ユーザーが決定した内容は次の 3 点。

1. 行データは CSV ファイルと Markdown 表の両方を受け付ける。
2. 親子関係は id / parent_id 方式と親パス方式の両方を、列名で判別して受け付ける。
3. 既存の 2 スペース tree ブロックの互換性を維持し、`├──` / `└──` / `│` 形式を追加する。

## 2026-10-21: D01〜D22 の採用決定

ユーザーは D01〜D22 の推奨案をすべて採用した。以下の要約・理由は 2026-10-20 の検討内容、回答欄は 2026-10-21 の採用記録である。選択肢と根拠は[ユーザー採用済み仕様設計書・工程記録](design-notes/row-and-tree-input-design.md)に検討履歴として残す。新しい CLI や解析機能、安全性改善は未実装であり、今回の反映は文書のみ。

個別に確認した決定:

- D01 / D02: 列名は標準英小文字の `id,parent_id,name,type` または `parent_path,name,type` のみ。`type` は必須で `file` / `directory` のみとし、列名・型値の別名は認めない。
- D05: 親パスの全祖先を行として明示する。途中のフォルダを省略した場合はエラーとし、暗黙の親を作らない。
- D15 / D16: Markdown では最初の tree を優先する。tree がなく候補表が一意なら自動選択し、複数なら `--source table:N` で明示選択する。対象を統合しない。`--input-format` / `--source` / `--tree-style` を分離する。
- D03・D04・D06〜D14・D17〜D22: 推奨案をまとめて採用した。
